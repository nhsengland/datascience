*Capturing and agreeing user requirements ensures outputs meet needs and expectations, with scope and constraints understood.*

**Success Criteria:** Requirements are agreed, documented, and kept under review through continuous dialogue with users.

* **RED:** No user engagement or scoping.
* **AMBER:** Basic project scope has been defined but difference in expectations between stakeholders may remain. User requirements were discussed at a point in time, but there is no regular ongoing dialogue or procedure for agreeing changes to requirements.
* **GREEN:** Scope of the project has been clearly defined and communicated to stakeholders. Stakeholders can raise changing needs and have these considered promptly. Any agreed changes to requirements are documented throughout project lifecycle.

## Good Practice Guidance

| MSC | Good Practice |
| --- | --- |
| MUST | * An agreed document (e.g. NWR form) sets out the agreed scope of deliverables. |
| SHOULD | * Stakeholders are available to actively engage with the data scientists, in order to appropriately shape the work |
| SHOULD | * There is a documented, shared understanding of how the end product is intended to be used. |
| SHOULD | * Investigations are carried out to understand the business problem in more detail |
| SHOULD | * User stories and use cases are identified and documented |
| SHOULD | * Key aspects of the problem, scope and complexities, including programme constraints, are captured and clearly communicated – potentially using the optional Scope Confluence template that is provided |
| SHOULD | * Boundaries are between the problem in question and other topical issues or problem areas, including any dependencies are identified. |
| SHOULD | * Any deviations from original requirements are set out and agreed with the stakeholders (ideally in writing). This should happen as soon as it is clear that deliverables will be impacted. |
| COULD | * Develop a Theory of Change map and narrative for the project. |

With [agile working comes an embrace for changing requirements,](https://agilemanifesto.org/)and therefore a continuous dialogue with the stakeholders must be maintained so that reviews, queries and changing needs can be accounted for in the work
