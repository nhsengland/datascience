*High-quality, appropriate data is the foundation for reliable analysis. Understanding sources, quality, and lineage is essential.*

**Success Criteria:** Relevant data sources identified, assessed, and documented with appropriate quality checks.

* **RED:** Data sources unclear or inappropriate.
* **AMBER:** Data sources identified but not fully assessed or documented.
* **GREEN:** Data sources appropriate, quality-checked, and documented.
* **NA:** Only if project involves no data use.

## Good Practice Guidance

| MSC | Good Practice |
| --- | --- |
| MUST | * Identify and review available data sources, selecting the most appropriate for your use case. |
| MUST | * Design effective procedures for data acquisition, including making formal agreements with providers where needed. |
| MUST | * Ensure all data processing complies with relevant information governance requirements. |
| MUST | * Consider risks to data quality, consistency and availability across the project lifecycle, and plan mitigations accordingly. |
| MUST | * Record assumptions regarding data completeness / coverage / units / filters applied. Consider actions required to verify such assumptions. |
| SHOULD | * Consult and contribute to the [Data Science Data Catalogue](https://nhsd-confluence.digital.nhs.uk/spaces/DAT/pages/841746323/Data+Catalogue) |
| SHOULD | * Understand and document the data’s lineage and any prior processing or transformation steps. |
| SHOULD | * Locate and review relevant documentation, such as data dictionaries, user guides, and quality issue logs. |
| SHOULD | * Put in place mechanisms to monitor data flows – particularly for regularly updated data – so issues are identified early. |
| COULD | * Engage with Information Asset Owners (IAOs) for advice and support. |
