# DS*xxx: QA Log*

The [Quality Framework for Data Science](../DS%20Quality%20Framework.md) is the collection of principles and good practice that enable us to deliver high-quality, assured products that meet user needs.

This QA Log is used to maintain an ongoing record of compliance with the various dimensions of the Quality Framework through the lifecycle of a project.

The log allows teams to:

- Carry out an effective self-evaluation
- Identify gaps and areas for improvement
- Signpost relevant evidence elsewhere in the project documentation
- Enable discussions about quality with the Commissioner, the Analytical Assurer, and other stakeholders
- Build an audit trail of decisions made through the project lifecycle to assure overall quality

Keep the Evidence column up to date as changes are made between reviews, but use this column as a reminder for the Assurer of what's changed since the last review. Can also use this column to propose changes to RAG status. |

## RAG ratings

- NA: If the quality dimension is not suitable for the project it does not need to be filled out. This needs to be a conversation with your Quality Assurer.
- Red: Requires immediate attention to enable delivery of a quality output
- Amber Will require attention before outputs are finalised and shared with customer / used to support decision making
- Greeng Sufficient and clear.

Refer also to the more detailed RAG guidance for each dimension.
