*The team is aware of the legal, ethical and security constraints relating to use of data and are able to work within them. All relevant IG approvals are in place with the necessary documentation.*

**Success Criteria:** Relevant IG requirements and approvals are identified, secured, and documented, ensuring compliance.

* **RED:** There is a chance the team is not working within the legal and security constraints. Necessary IG approvals are missing or undocumented.
* **AMBER:** Most of the necessary IG approvals are in place, sufficient for current phase of work. There may still be some gaps or uncertainties that need to be addressed to complete project delivery.
* **GREEN:** All relevant IG approvals are in place with the necessary documentation, ensuring the project is legally compliant and secure.

## Good Practice Guidance

| MSC | Good Practice |
| --- | --- |
| MUST | * Establish what IG documentation is necessary-  for example a  Data Protection Impact Assessment. |
| MUST | * Take steps to complete necessary IG documentation. |
| MUST | * Have a culture of openness around errors and near misses, for example by reporting data breaches. |
| MUST | * Comply with any requirements arising from patient opt-out |
| MUST | * Use sensitive and/or confidential personal data only when necessary, and to the minimum necessary, documenting requirements for such use. Completing a DPIA will require documentation of such consideration. |
| MUST | * Ensure all team members are up-to-date with mandatory e-learning regarding data use. |
| SHOULD | * Engage with Information Asset Owner for each data asset to gain approval for  project’s specific use. |
| SHOULD | * Consider if the project will create a new asset i.e., a new data set requiring an IAO. |
