# 📦 Project Closure

_Closing projects properly ensures knowledge, outputs, and assets are preserved and accessible for future use._

_The success criteria below apply for end-stage projects. However, closure planning should begin from project inception. This helps to ensure there is a clear and realistic plan for how the product, model, pipeline, or service will operate once development is complete, e.g. ownership, BAU processes, service expectations. A proportionate **BALANCE** should be maintained between planning for closure early and avoiding unnecessary overhead for early-stage projects. As soon as possible, projects should have an appropriate vision for some (AMBER) or all (GREEN) elements of project closure. This should be documented and loosely agreed with stakeholders and any collaborating teams._

**Success Criteria:** Closure activities have been completed, with models, code and outputs stored in line with guidelines.

- **RED:** Project closure activities are not identified or completed. Critical outputs not stored in a controlled system.
- **AMBER:** Critical outputs stored, but wider project closure activities may be neglected - limiting audit-ability and knowledge retention / reuse for subsequent projects.
- **GREEN:** All project closure /transition activities are completed. All outputs, decision logs, working materials and other documentation completed and stored to enable reuse, marketing of work, audit-ability and knowledge transfer.
