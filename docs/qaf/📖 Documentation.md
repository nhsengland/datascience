# 📖 Documentation

_Clear documentation makes projects understandable, reproducible, and accessible to others, supporting trust and reuse._

**Success Criteria:** Documentation is comprehensive, accessible, and sufficient for others to understand, reproduce, and use outputs.

- RED: Documentation inadequate or absent.
- AMBER: Documentation present but with gaps or inconsistencies.
- GREEN: Comprehensive, accessible documentation of all systems, code, and procedures.

## Good Practice Guidance

| MSC    | Good Practice                                                                                                                                                                                                 |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MUST   | \* There is sufficient documentation to allow the use of the product as intended by end-users. It is accessible by the users                                                                                  |
| MUST   | \* Key elements of code-base have in-line documentation.                                                                                                                                                      |
| MUST   | \* Key processes that have an element of manual execution during BAU running are supported by 'runbook' documentation.                                                                                        |
| SHOULD | \* End-user documentation is reviewed and critiqued by a 'fresh pair of eyes' end-user - ideally using documentation to follow intended end-user journey independently.  Feedback is captured and acted upon. |
| SHOULD | \* There is a clear plan and standard for documentation of code, following good-practice use of (e.g.) docstring.                                                                                             |
| SHOULD | \* Definition of 'done' for tasks includes completion of relevant documentation.                                                                                                                              |
